# Dr. Joy RDH: website

A six-page, photo-led personal website for Dr. Joy RDH. It has separate pathways for speaking, hands-on education, industry collaborations and consulting (which links out to Instrumental).

Built with Next.js 16 and Tailwind CSS 4. The look is black and white: white pages, black sections, neutral greys for secondary text and thin divider lines. The photographs, in full color under one shared grade, bring the warmth. The one accent is a pale pink marker behind a phrase that matters, used once or twice a page and only on white. Type is two families beside the script logo: Archivo (bold, a little wide) for headings and DM Sans for everything else.

## Run it

```bash
npm install
```

```bash
npm run dev
```

Open http://localhost:3000. To test forms locally, copy `.env.example` to `.env.local` and set `GHL_WEBHOOK_URL`.

### Review mode

`showPlaceholders` in `src/content/site.ts` is `true` while the site is in review. In that mode:

- the whole site asks search engines not to index it (`noindex`)
- content still awaiting Dr. Joy's approval is shown so she can approve it: testimonials awaiting permission, the venue list, unconfirmed articles
- links whose address is still missing (Instrumental) go nowhere

The preview carries no working notes, so it looks as visitors will see it. To see what is still pending, set `reviewNotes` to `true` as well. That adds:

- "URL pending", "To confirm" and "Permission to republish pending" tags
- labelled empty slots: photo art direction, logo boxes, article slots, the speaker reel
- notes such as "confirm before launch"

Set it to `false` for launch. Then:

- anything still empty is hidden, including empty photo slots, so the site never shows a dead link, a placeholder or an empty section
- review tags disappear and the `noindex` is lifted
- the launch checks run: the build **fails** with a list if `links.instrumental` is missing, if `links.privacy` is missing while a form offers the text-message opt-in, or if `site.url` is not the production address (`launchBlockers()` in `site.ts`)

### Proportions, type scale and lines

One page column and one type scale serve every page (`src/app/globals.css`):

- **Column.** `--wrap` is 76rem, used as `max-w-(--wrap)`. On a desktop it leaves about a tenth of the screen clear on each side. Sections are padded about 5rem top and bottom on phones and 7rem on desktop.
- **Headings.** A heading takes `display` and one size: `t-hero` (a page's opening line, 64px on a desktop and 36px on a phone), `t-h1` (a section heading, 48px), `t-h2` (34px) or `t-h3` (22px). Nothing is set larger than `t-hero`. Running text takes `t-lead` or `t-body`; small capital labels take `label`.
- **Typefaces.** Two, beside the script logo: Archivo for headings and DM Sans for everything else (`src/app/layout.tsx`). Headings use one cut of Archivo, bold and 112% wide, kept as a small file in `src/app/fonts` (its README says how it was made); a heading at another weight or width needs a new cut. DM Sans is loaded upright only.
- **Emphasis.** Never italic and never a second typeface. A heading is plain, or one phrase carries the pale pink marker behind it (`<Hl>`, `src/components/motion/Text.tsx`). The marker is for white sections only: black sections carry no pink.
- **Photographs.** Beside text a photograph takes four or five of the twelve columns, about a third of the screen. A wide photograph may run the width of the column as a band. One photograph fills the screen: the story on Home (below). A portrait with its background removed (`treatment: "cutout"`) stands on the bottom edge of its section, straight on white or black.
- **Lines.** Where one white section follows another, a thin grey line the width of the column is drawn between them automatically; a section that should run on from the one above takes the class `no-rule`. Lists and ledgers use thin lines between groups (`border-line` on white, `border-line-dark` on black). Black sections need no line: the change of color is the edge.

### Opening screen

Home opens on a black stage: the headline on the left and Dr. Joy's portrait in the white blazer on the right, in color with its background removed, standing on the bottom edge of the section. It is one screen tall on a desktop. The component is `src/components/home/Hero.tsx` and the portrait is `home.hero.photo`.

### Home's story

After the opening, "A perspective shaped by every side of dentistry." is the one full-screen picture on the site. It arrives as a title spread (the heading on white above the framed photograph); the frame opens until the whole photograph fills the screen, the light goes down on the side away from her, and the five approved statements appear there one at a time in white, with a counter and a thin progress line. The next section then slides up over it. On landscape screens she stands on the left and the words are set on the right (`home.perspective.photo`, the wide frame); on phones and upright tablets she fills the screen and the words sit low (`photoTall`, a 4:5 crop of the same photograph).

The component is `src/components/home/Perspective.tsx` and the choreography is in `src/app/styles/home.css` ("The story"). The type stays inside the site's scale: the statements are never larger than a section heading. Without JavaScript, with reduced motion, in print, and on screens too small for the words, it is a plain section: the photograph, the heading and the statements as reading text.

The supplied SVGs include a solid background panel; it has been removed and each frame cropped to the mark. The page colors are tokens in `src/app/globals.css`: ink, paper, a soft grey fill (`mist`), two text greys (`stone` on white, `ash` on black) and the divider lines. ### The opening signature

On every full page load, including a refresh, a black curtain carries the script wordmark and signs it: the line is drawn stroke by stroke in handwriting order (the entry flourish, d, r, the full stop, j, o, y, the closing flourish), the capitals rise under the last stroke, a thin line draws beneath, and the curtain lifts into the page. Any click, tap, key or scroll skips it. It does not play when moving between pages inside the site, on Back or Forward, with reduced motion, or without JavaScript.

- How long the writing takes is one value, `--intro-wd` in `src/app/styles/chrome.css` (with `--intro-w0`, the pause before the pen starts, and `--intro-beat`, the hold before the curtain lifts).
- The pen's path lives in `src/components/chrome/signature-data.ts` and is generated from the wordmark file by `scripts/signature/` (two steps, described at the top of `trace.py`; it needs scikit-image, SciPy and NetworkX, which are not project dependencies). Only rerun it if the wordmark artwork changes; the same artwork is also held as a data URI in `chrome.css`.
- For tests and screenshots, `sessionStorage.setItem("dj-intro-off", "1")` before the page loads switches the curtain off.

The share image (`src/app/opengraph-image.jpg`, also `twitter-image.jpg`, 1200×630) follows the Home opening screen: the white-blazer portrait in color on black, the cream wordmark and the approved Home headline. Rebuild it if the opening screen changes, and check it in the LinkedIn Post Inspector and the Facebook Sharing Debugger after the first deploy.

## Photos

`public/photos/` holds web versions of the selected shoot and event photographs. Each photo slot in the content files records the `original` filename from the Drive folder, so any image can be traced back for retouching or replacement.

- Export masters at 2400 px on the long edge (1600 px is fine for small slots), JPEG quality about 82, progressive, sRGB, metadata stripped.
- Never overwrite a photo: give a replacement a new filename. Optimized images are cached for 31 days, keyed on the filename.
- Portraits have a black-and-white twin (`srcBw`); `photoStyle` in `site.ts` switches every portrait at once. The conversions use a skin-preserving channel mix and a gentle curve. If the photographer supplies their own conversions, drop them in under the same names.
- After adding or replacing photos, run `npm run photos:blur`. It writes a tiny preview of each JPEG to `src/content/blur.json`; while a photo loads, its frame shows that soft color preview and the photo fades in over it. Photos without a preview simply wait for the photo before revealing.
- Color grade: every color photo carries one shared, restrained grade, so the set reads as one shoot. Violet and blue stage light is calmed (hues around 262°; skin and whites are untouched), saturation is 8% lower overall, the black point is lifted about 3%, and the white balance leans neutral-warm. `npm run photos:grade` (Python 3 with Pillow and NumPy) grades every color photo referenced in `src/` into a new `-g` file, never overwriting, and updates the references. Black-and-white twins and PNG cutouts are not graded. Then run `npm run photos:blur`. The recipe lives in `scripts/grade_photos.py`.
- Louder photos take opt-in extras; without the flags the grade is exactly as above. A photo re-graded this way gets a `-v2-g.jpg` name.
  - `--foliage 0.45` adds a second band that calms foliage, teal and chartreuse (hues around 125°).
  - `--ceiling 0.30` brings the photo's mean saturation down to 0.30 by calming saturated hues outside skin; skin and lips are never touched, and calmed colors keep their lightness.
  - `--stage 0.6` calms stage light harder than the default 0.45.
  - In use: the Meet hero, the Meet operatory close-up and the Insights hero take `--foliage 0.45 --ceiling 0.30`, the Industry launch frame `--foliage 0.45 --ceiling 0.26`, and the Speaking keynote `--stage 0.6`.
  - Grade from the ungraded crop rebuilt from the Drive original, never from a `-g` file: `python3 -I scripts/grade_photos.py crop.png public/photos/<name>-v2-g.jpg --foliage 0.45 --ceiling 0.30`.
- Black-and-white twins: `npm run photos:bw -- public/photos/<name>-g.jpg public/photos/<name>-bw.jpg` (`scripts/bw_twin.py`).
- Three pages open on a portrait with its background removed, in full color, straight on the page: Home on black (`home-hero-cutout-133.webp`), Meet Dr. Joy on white (`meet-hero-cutout.webp`, supplied by Dr. Joy at 1122 × 1402) and Industry Collaborations on white (`industry-hero-cutout-155.webp`). Speaking, Hands-On Education and Insights keep photographs with their settings: the room is part of the story there.
  - The Home and Industry cut-outs were made here from the graded frames `meet-hero-133-g.jpg` and `home-hero-g.jpg` with `scripts/cutout.py` (requirements and steps are at the top of that file). Both source frames stay in `public/photos` for that reason.
  - The photographs they replaced are still in `public/photos`: `home-hero-stage-tall-g.jpg` (JVH-111 on the steps) and `industry-hero-4x5-g.jpg` (JVH-129, seated). To go back, point the slot's `src` at the file and set `treatment: "color"`.
  - Replace Dr. Joy's own cut-out with the full-resolution file when it arrives: a transparent PNG or WebP at least 1800 px wide, under a new filename.
- Meet Dr. Joy uses a candid frame from the portrait shoot (JVH-167) as its life photo. When Dr. Joy supplies a Bowie Boys and Girls Club photo, set it as `meet.guides.photo` (color, no B&W twin needed) and grade it with `npm run photos:grade`. An empty slot is hidden at launch and the story column takes its place.

## Motion

Motion uses one tempo, set as tokens in `src/app/globals.css`: hover 180 ms, interface 320 ms, text reveals 600 ms, photo uncovers and headline lines 800 ms.

Scroll effects (words that light as they are read, photographs that drift, the few pinned sequences) use no animation library. One small inline script (`src/components/motion/engine.ts`) turns scroll position into CSS variables and attributes, and the styles in `src/app/styles/motion.css` and each page's stylesheet read them. The building blocks are in `src/components/motion/`; `/motion-lab` shows each one (review mode only).

Everything is scoped to `<html class="motion">`, which is set only when JavaScript runs and the visitor has not asked for reduced motion. Without it every page is its plain, complete layout: all words and photographs are in the server HTML, nothing waits on a script, and nothing moves.

The whole site scales up on large screens: sizes are in rem, and the root font size grows with the window above 1440 px wide (see `html` in `globals.css`), so a 2560 px monitor shows the 1440 px composition, larger. Write new sizes in rem, not px.

## Forms and GoHighLevel

Every form posts to `/api/inquiry`. That route validates the submission, drops spam (a hidden honeypot field) and forwards JSON to `GHL_WEBHOOK_URL`. A single webhook can route on the tag, or use the per-type override variables in `.env.example`.

| Inquiry | Opened from | Tag |
| --- | --- | --- |
| Speaking (talk or keynote) | Speaking page, footer, general flow | `speaking` |
| P3 for my conference | Speaking › Dr. Joy's P3 | `p3-conference-inquiry` |
| P3 interest list | Hands-On Education (when no event page is live) | `p3-interest-list` |
| Sponsorship / KOL partnership | Industry Collaborations | `manufacturer-partnership-kol` |
| Clinical launch strategy | Industry Collaborations | `clinical-launch-strategy` |
| General ("Start a Conversation") | Header, Home closing | `general-inquiry` |
| From Dr. Joy newsletter | Footer, Insights | `newsletter-from-dr-joy` |

The general flow asks what the visitor needs:

- **Consulting** routes to Instrumental instead of a form.
- **Attend a P3 event** goes to the live event page when one is set, otherwise to the interest list.

The footer also opens the P3 conference, interest-list and clinical-launch forms. The footer newsletter is hidden on `/insights` and `/insights/*`, which have their own signup.

Besides the form fields and `tags`, the payload carries `program` (speaking: the program of interest), `sponsor_consent_text` and `sms_consent_text` (the exact wording agreed to), `consent_version` and `consent_recorded_at`. Bump `optInsVersion` in `integrations.ts` whenever the opt-in wording changes. `sponsor_opt_in` and `sms_opt_in` are sent only for the P3 interest list, the one form that asks. The route returns 422 for a text-message opt-in without a phone number. The webhook call times out after 10 seconds, and the error message offers a prefilled email instead.

The P3 interest list has two separate opt-ins: sponsor communications and text messages. Both are unchecked by default. Choosing text messages requires a phone number. **The opt-in language in `integrations.ts` needs review before launch**, and because text-message consent is collected, the site needs a published privacy policy (`links.privacy`).

### P3 event

Set `education.events.featured` (in `src/content/education.ts`) to the next event, using Hazel's live landing-page URL (https) as `registrationUrl` (the build stops if it is not a live https address); the comments there describe the other fields, including when a past event falls back on its own. While it is `null`, the page shows the approved "not yet available" message and the interest-list form, so there is never a dead registration link. While an event is live, Hands-On also carries its schema.org Event data, and it comes down with the event.

## Search and sharing

- Titles use the page name plus "| Dr. Joy RDH". Descriptions come from approved copy. Every page has its own canonical URL and share URL, built from `site.url`.
- `sitemap.xml` lists the six pages; `robots.txt` points to it.
- Structured data (schema.org Person and WebSite) is rendered once, in the root layout, plus an Event on Hands-On while a featured event is live. It uses approved copy only; `site.fullName` stays empty until Dr. Joy confirms her full name may be used, and `links.profiles` can list her public profiles.
- `next.config.ts` redirects every address of the old WordPress site (46 URLs from its sitemap) to the closest new page. Consulting addresses go to Instrumental once `links.instrumental` is set; the old privacy and terms pages go to `links.privacy` and `links.terms` once set. The files the old meeting-planner page linked (bios, logistics, headshots, speaker kit) land on the Speaking resources (`/speaking#resources`); the speaker kit goes to `links.speakerResources` once it is set.
