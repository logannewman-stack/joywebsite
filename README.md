# Dr. Joy RDH: website

A six-page, photo-led personal website for Dr. Joy RDH. It has separate pathways for speaking, hands-on education, industry collaborations and consulting (which links out to Instrumental).

Built with Next.js 16 and Tailwind CSS 4. The look is a black-and-white editorial foundation, with ivory for warmth and blush as a restrained accent. Type is Instrument Serif for display and Geist for text.

## Run it

```bash
npm install
```

```bash
npm run dev
```

Open http://localhost:3000. To test forms locally, copy `.env.example` to `.env.local` and set `GHL_WEBHOOK_URL`.

### Review mode

`showPlaceholders` in `src/content/site.ts` is `true` while the site is in review. In that mode:

- the whole site asks search engines not to index it (`noindex`)
- empty photo slots show their art direction
- logo walls, articles and the attendee testimonial show labelled slots
- unconfirmed published articles show "To confirm"
- testimonials awaiting permission carry a "Permission to republish pending" tag
- links whose address is still missing (Instrumental) carry a "URL pending" tag and go nowhere
- `/directions` is available

Set it to `false` for launch. Then:

- anything still empty is hidden, including empty photo slots, so the site never shows a dead link, a placeholder or an empty section
- review tags disappear, `/directions` returns 404 and the `noindex` is lifted
- the launch checks run: the build **fails** with a list if `links.instrumental` is missing, if `links.privacy` is missing while a form offers the text-message opt-in, or if `site.url` is not the production address (`launchBlockers()` in `site.ts`)

## Brand assets

`public/brand/` holds the Dr. Joy script wordmark and the JD monogram, taken from "New Dr Joy RDH Logos" (variants -04 charcoal and -01 cream). The supplied SVGs include a solid background panel; it has been removed and each frame cropped to the mark. The favicon (`src/app/icon.svg`) is the primary monogram on charcoal; `apple-icon.png` (180 px) and `favicon.ico` (16, 32, 48 px) are rendered from it.

Brand colors come from the logo files: cream `#F5F1E9`, blush `#E7D3CB`, charcoal `#393839`. Gold appears only in the logo files and is not used for type on the site.

### The opening signature

On every full page load, including a refresh, a black curtain carries the script wordmark and signs it: the line is drawn stroke by stroke in handwriting order (the entry flourish, d, r, the full stop, j, o, y, the closing flourish), the capitals rise under the last stroke, a gold hairline draws beneath, and the curtain lifts into the page. Any click, tap, key or scroll skips it. It does not play when moving between pages inside the site, on Back or Forward, with reduced motion, or without JavaScript.

- How long the writing takes is one value, `--intro-wd` in `src/app/styles/chrome.css` (with `--intro-w0`, the pause before the pen starts, and `--intro-beat`, the hold before the curtain lifts).
- The pen's path lives in `src/components/chrome/signature-data.ts` and is generated from the wordmark file by `scripts/signature/` (two steps, described at the top of `trace.py`; it needs scikit-image, SciPy and NetworkX, which are not project dependencies). Only rerun it if the wordmark artwork changes; the same artwork is also held as a data URI in `chrome.css`.
- For tests and screenshots, `sessionStorage.setItem("dj-intro", "1")` before the page loads switches the curtain off.

The share image (`src/app/opengraph-image.jpg`, also `twitter-image.jpg`, 1200×630) follows the Home opening screen: JVH-111 in color on black, the cream wordmark and the approved Home headline. Rebuild it if the opening screen changes, and check it in the LinkedIn Post Inspector and the Facebook Sharing Debugger after the first deploy.

## Photos

`public/photos/` holds web versions of the selected shoot and event photographs. Each photo slot in the content files records the `original` filename from the Drive folder, so any image can be traced back for retouching or replacement.

- Export masters at 2400 px on the long edge (1600 px is fine for small slots), JPEG quality about 82, progressive, sRGB, metadata stripped.
- Never overwrite a photo: give a replacement a new filename. Optimized images are cached for 31 days, keyed on the filename.
- Portraits have a black-and-white twin (`srcBw`); `photoStyle` in `site.ts` switches every portrait at once. The conversions use a skin-preserving channel mix and a gentle curve. If the photographer supplies their own conversions, drop them in under the same names.
- After adding or replacing photos, run `npm run photos:blur`. It writes a tiny preview of each JPEG to `src/content/blur.json`; while a photo loads, its frame shows that soft color preview and the photo fades in over it. Photos without a preview simply wait for the photo before revealing.
- Color grade: every color photo carries one shared, restrained grade, so the set reads as one shoot. Violet and blue stage light is calmed (hues around 262°; skin and whites are untouched), saturation is 8% lower overall, the black point is lifted about 3%, and the white balance leans neutral-warm. `npm run photos:grade` (Python 3 with Pillow and NumPy) grades every color photo referenced in `src/` into a new `-g` file, never overwriting, and updates the references. Black-and-white twins and PNG cutouts are not graded. Then run `npm run photos:blur`. The recipe lives in `scripts/grade_photos.py`.
- Louder photos take opt-in extras; without the flags the grade is exactly as above. A photo re-graded this way gets a `-v2-g.jpg` name.
  - `--foliage 0.45` adds a second band that calms foliage, teal and chartreuse (hues around 125°).
  - `--ceiling 0.30` brings the photo's mean saturation down to 0.30 by calming saturated hues outside skin; skin and lips are never touched, and calmed colors keep their lightness.
  - `--stage 0.6` calms stage light harder than the default 0.45.
  - In use: the Meet hero, the Meet operatory close-up and the Insights hero take `--foliage 0.45 --ceiling 0.30`, the Industry launch frame `--foliage 0.45 --ceiling 0.26`, and the Speaking keynote `--stage 0.6`.
  - Grade from the ungraded crop rebuilt from the Drive original, never from a `-g` file: `python3 -I scripts/grade_photos.py crop.png public/photos/<name>-v2-g.jpg --foliage 0.45 --ceiling 0.30`.
- Black-and-white twins: `npm run photos:bw -- public/photos/<name>-g.jpg public/photos/<name>-bw.jpg` (`scripts/bw_twin.py`).
- Meet Dr. Joy uses a candid frame from the portrait shoot (JVH-167) as its life photo. When Dr. Joy supplies a Bowie Boys and Girls Club photo, set it as `meet.guides.photo` (color, no B&W twin needed) and grade it with `npm run photos:grade`. An empty slot is hidden at launch and the story column takes its place.

## Motion

Motion uses one tempo, set as tokens in `src/app/globals.css`: hover 180 ms, interface 320 ms, text reveals 600 ms, photo uncovers and headline lines 800 ms. Reveals are visible in the server HTML and without JavaScript, and everything is still for visitors who ask for reduced motion.

## Forms and GoHighLevel

Every form posts to `/api/inquiry`. That route validates the submission, drops spam (a hidden honeypot field) and forwards JSON to `GHL_WEBHOOK_URL`. A single webhook can route on the tag, or use the per-type override variables in `.env.example`.

| Inquiry | Opened from | Tag |
| --- | --- | --- |
| Speaking (talk or keynote) | Speaking page, footer, general flow | `speaking` |
| P3 for my conference | Speaking › Dr. Joy's P3 | `p3-conference-inquiry` |
| P3 interest list | Hands-On Education (when no event page is live) | `p3-interest-list` |
| Sponsorship / KOL partnership | Industry Collaborations | `manufacturer-partnership-kol` |
| Clinical launch strategy | Industry Collaborations | `clinical-launch-strategy` |
| General ("Start a Conversation") | Header, Home closing | `general-inquiry` |
| From Dr. Joy newsletter | Footer, Insights | `newsletter-from-dr-joy` |

The general flow asks what the visitor needs:

- **Consulting** routes to Instrumental instead of a form.
- **Attend a P3 event** goes to the live event page when one is set, otherwise to the interest list.

The footer also opens the P3 conference, interest-list and clinical-launch forms. The footer newsletter is hidden on `/insights` and `/insights/*`, which have their own signup.

Besides the form fields and `tags`, the payload carries `program` (speaking: the program of interest), `sponsor_consent_text` and `sms_consent_text` (the exact wording agreed to), `consent_version` and `consent_recorded_at`. Bump `optInsVersion` in `integrations.ts` whenever the opt-in wording changes. `sponsor_opt_in` and `sms_opt_in` are sent only for the P3 interest list, the one form that asks. The route returns 422 for a text-message opt-in without a phone number. The webhook call times out after 10 seconds, and the error message offers a prefilled email instead.

The P3 interest list has two separate opt-ins: sponsor communications and text messages. Both are unchecked by default. Choosing text messages requires a phone number. **The opt-in language in `integrations.ts` needs review before launch**, and because text-message consent is collected, the site needs a published privacy policy (`links.privacy`).

### P3 event

Set `education.events.featured` (in `src/content/education.ts`) to the next event, using Hazel's live landing-page URL (https) as `registrationUrl` (the build stops if it is not a live https address); the comments there describe the other fields, including when a past event falls back on its own. While it is `null`, the page shows the approved "not yet available" message and the interest-list form, so there is never a dead registration link. While an event is live, Hands-On also carries its schema.org Event data, and it comes down with the event.

## Search and sharing

- Titles use the page name plus "| Dr. Joy RDH". Descriptions come from approved copy. Every page has its own canonical URL and share URL, built from `site.url`.
- `sitemap.xml` lists the six pages; `robots.txt` points to it. `/directions` is never listed.
- Structured data (schema.org Person and WebSite) is rendered once, in the root layout, plus an Event on Hands-On while a featured event is live. It uses approved copy only; `site.fullName` stays empty until Dr. Joy confirms her full name may be used, and `links.profiles` can list her public profiles.
- `next.config.ts` redirects every address of the old WordPress site (46 URLs from its sitemap) to the closest new page. Consulting addresses go to Instrumental once `links.instrumental` is set; the old privacy and terms pages go to `links.privacy` and `links.terms` once set. The files the old meeting-planner page linked (bios, logistics, headshots, speaker kit) land on the Speaking resources (`/speaking#resources`); the speaker kit goes to `links.speakerResources` once it is set.
